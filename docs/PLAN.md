## 1. 建模原则（硬约束，优先级高于本文其余部分；与 v2 相同，仅 §1.5 改写、新增 §1.8）

### 1.1 参数来源分级
每个进入模型的数都必须登记在 `data/params/registry.yaml`（名称、数值、单位、级别、出处、不确定度范围、登记日期、是否已核对原文）。没有登记的数不得出现在 `configs/`、`src/` 或 `pluto/` 的物理部分；`scripts/check_provenance.py` 在测试阶段强制检查（v3 起同时扫描 `pluto/*.c`、`*.h`）。

### 1.2 禁止事项
1. **禁止以待比较数据为目标调整任何 A–F 级物理输入或 N 级数值参数。** 比较集指：图 S3、S4、S5、S7、图 2、图 4 中的羽流边界、S12 的羽流部分，即两种通量下的全部羽流发光数据。
2. 独立检验集（图 3d 与 S6 的冲击波轨迹、图 5b 凹坑尺寸）同样**不得用于调参**，只用于检验能量收支（分支 B 是唯一例外，见 §4.5）。
3. 禁止参数搜索、优化、贝叶斯标定、按损失函数挑选算例。
4. 禁止逐帧的增益、平移、缩放或时间调整。
5. 禁止引入没有独立出处的乘性修正系数（例如"冷却倍率""吸收增强因子"）。
6. 禁止只报告吻合好的情景、指标或阶段；事先声明的全部情景、指标与 v0/v1/冻结基线各阶段结果都要报告。
7. 禁止把历史 PLUTO/COMSOL 的拟合值当作先验。历史工程的 14 个拟合量（质量、能量、动能份额、尾部、源高度、线宽、增益、靶面位置、PSF、时间偏移、水平平移等）**一个都不进入 v3**；`prior/` 只读。

### 1.4 敏感性分析与"调参"的区别
- **敏感性分析**：输入在事先登记的不确定度范围内变化（范围来自文献分歧或测量误差，与比较集无关），所有成员的结果都报告，给出的是**不确定度带**与影响排序。基线值不因敏感性结果而改变。
- **调参**：根据与实验的吻合程度选择或修改输入值。本项目不做。
- 操作规则：(1) 敏感性设计写入 PREREG 后再运行；(2) 结果图中基线用实线、成员用带，不得把最接近实验的成员单独标出；(3) 若某输入在其合理范围内能显著改善吻合，表述为"结果对该输入敏感，其不确定度是差异的可能来源之一"，而不是"取该值后吻合"。

### 1.5 冻结、登记与偏离记录
1. **冻结（两次，见 §1.8）**：`docs/PREREG_v0.md` 在任何 v0 二维算例与比较集对比之前提交；`docs/PREREG.md` 在 D5 冻结最终基线。内容：模型方程、登记表哈希、物性表哈希、PLUTO 压缩包与用户模块哈希、指标定义、通过标准、情景与敏感性设计、升级阶梯。git 时间戳为证。
2. **运行登记**：每一个二维运行（包括失败、中止、调试、保底预跑）由程序自动追加到 `results/run_registry.csv`（时间、提交号、配置哈希、目的、是否完成）。补充材料给出登记表，证明没有挑选。
3. **偏离记录**：冻结后只允许两类修改：(a) 改正错误（代码缺陷、抄错的常数、单位错误），须有独立于比较集的证据；(b) 作者提供了新的 E 级信息。每次修改追加一条记录，修改前后的结果都保留并都报告。
4. **诚实说明**：规划者与执行者都看过 S4/S7 与历史拟合结果，这不是严格意义的盲预测。可信度由参数出处规则、冻结与全量登记保证，论文中照此表述。

### 1.6 模型形式升级的规则
物理模型形式的升级只能由**事先声明的清单（§1.8）或模型内部的有效性诊断（§3.6）**触发，不能由"与实验不像"触发。每一级的结果都保留并报告。与实验比较之后的探索必须标注为"事后探索"，单独成节，不替换冻结基线的结果。

两周内无法"先把模型做完再第一次比较"。为了不让"看了 v0 的比较结果再决定加什么"变成变相调参，规则如下：

## 2. 目标与已核对事实（详见 `docs/DATA_NOTES.md`、`docs/PRIOR_DIAGNOSIS.md`）
- 复现图 S4（高通量，29 帧，0–740 ns）的侧视亮度图与同款图像处理得到的曲线；同一模型不改参数给出低通量（S3）与冲击波轨迹（图 3d）。重点是 60 ns 之后的整体趋势，特别是后期变淡。
- 实验条件（D 级）：Cu C1100；1064 nm、60 ns、单脉冲、1 atm 空气；高通量 0.4 mJ、1/e² 直径 22 µm（峰值功率约 6.3 kW、轴心峰值强度约 3.3 GW/cm²）；低通量 0.32 mJ、直径 31 µm（约 5.0 kW、1.3 GW/cm²）。
- 实验主指标（`data/exp/`）：τ_L 高 182 ns / 低 218 ns；Δt₁₀ 高 433 / 低 542 ns；尺寸二阶矩高通量约 300–400 ns 转折、低通量约 400–600 ns；冲击波 ≥ 300 ns 速度 542 / 521 m/s，R(500 ns) ≈ 614 / 588 µm。
- 历史 PLUTO 最佳例的问题（T004）：后期发光区 10.7→9.4 kK 几乎不冷却；带内代表线上能级错用 3.82 eV（应为 Cu I 515.32/521.82 nm 的 6.19 eV）；辐射只有一条线 + free–free；EOS 截断在 Cu⁺/中性空气；能量 180 µJ、质量 4.34 ng（41 MJ/kg）为拟合且贴边界；光斑按半径 22 µm。

### 3.7 控制方程（v1 完整形式；v0 去掉输运项，靶为单向）
```
∂ρ/∂t + ∇·(ρu) = S_m            ∂(ρY)/∂t + ∇·(ρYu) = S_m [+ ∇·(ρD∇Y)]
∂(ρu)/∂t + ∇·(ρuu + pI) = ∇·τ + S_mom
∂E/∂t + ∇·((E+p)u) = ∇·(κ∇T) + ∇·(τ·u) + Q_las − Q_rad + S_E
p, T, nₑ = EOS(ρ, e, Y)（表格）     Q_rad = 4π·NEC     Q_las = α₁₀₆₄·(I↓ + I↑)，dI/dz = ∓α₁₀₆₄ I
靶：∂H/∂t = ∂/∂z(k ∂T/∂z)；表面 −k ∂T/∂z = A(T_s)·I_s − ṁ·L_v(T_s)；ṁ、T_v、ρ_v、u_v 由 Knudsen 层关系给出
```
S_m、S_mom、S_E 只在靶面第一层单元非零。初始 1 atm、293.15 K 静止空气；r = 0 对称轴；外边界出流。

## 4. 能量与质量来源

### 4.1 计算链（没有任何一步以质量或能量为输入）
`P(t)、w₀`（D）→ `靶面吸收 A(T_s)·I_s`（C）→ `靶升温、熔化、蒸发：ṁ(r,t)`（C/F）→ `蒸气与激波后空气的 LTE 电离度`（A/B）→ `α₁₀₆₄(ρ,T,Y)`（B/C）→ `二维气相吸收与屏蔽：到达靶面的光强下降` → 回到靶（v0 用 Picard 迭代闭环，v1 逐步耦合）。
为什么直接在二维上算而不先做一维：光斑半径 11 µm 远小于脉冲期间羽流尺度，侧向膨胀决定屏蔽强弱，一维模型会系统性高估吸收；且流体核现成，二维粗网格算例只需几十分钟（估计）。

### 4.2 收支记账
PLUTO 的 `Analysis()` 每步累计并写 `budget.csv`：入射、靶面反射逃逸、靶吸收（导走/熔化/汽化/超限记账）、气相吸收（去程与回程）、蒸气带入的质量与焓、累计辐射、出域通量、域内总能量与铜质量。残差要求 < 0.1%（v0 第 0 次迭代的靶–气不自洽量单独列出，不算残差）。**气相吸收占比、汽化质量、辐射占比、屏蔽开始时刻都是预测结果，没有目标值。**

### 4.3 点燃关 G1（在二维 v0 上判定；判据只用模型内部量）
- 判据（F 级，事先声明）：脉冲结束时（t = 150 ns）气相吸收能量 ≥ 脉冲能量的 5%，且脉冲期间气相最高温 ≥ 1.5×10⁴ K → "已点燃"。同时报告吸收能量对网格（G0/G1/G2）与 Picard 迭代的变化；G1→G2 变化 > 10% 记为"未收敛"，只允许加密近壁网格（N 级）。
- 独立文献检验（D2–D4，精简自 v2 的 V12b/c）：用同一套模块在准一维（大光斑）构型下扫描通量，给出 Cu 在 1064 nm 纳秒脉冲下的点燃阈值与烧蚀深度量级，与已发表数据相差不超过 2 倍；不看本论文羽流数据。
- 若"未点燃"：**不允许手工注入能量后称为预测。** 按 DECISIONS 2026-11-15 第 2 条启用分支 B，作为并列的、明确标注"半经验"的变体。v2 的点燃阶梯 I1（电子能量方程 + 有限速率电离）不在两周范围内，列为局限。

### 4.4 能量收支的独立检验（不得用于调参）
1. 冲击波轨迹 R_s(t) 与图 3d 比较（P4）。
2. 能量反推（T009）：未改动 PLUTO 的理想气体半球点爆炸（含背压）对图 3d 给出 E_blast 区间，与模型的"气相吸收 − 辐射损失"比较，报告比值；R ∝ E^0.2，分辨力约 2 倍。
3. 汽化质量与图 5b 凹坑尺寸的量级比较（凹坑含熔体排出，只是上界）。

### 4.5 分支 B（半经验保底；用户已同意其地位）
- 内容：气相总吸收能量取 T009 的 E_blast 区间（低/中/高三个成员全部报告）；空间分布仍取同一射线推进算出的 α·I 分布，每步总功率重整化为 f_B·P(t)；铜质量仍由靶模型给出。此时图 3d 不再算作验证。

## 5. 软件路线：唯一推荐

**推荐：以未改动的 PLUTO 4.4-patch4 内核为唯一生产流体核 + 本项目自写的用户模块；`lipsim`（Python）做物性表、靶/蒸发源、成像、指标、批处理与报告。v2 的"自写 lipsim 流体核"取消。**

| 准则 | PLUTO 内核 + 自写模块（v3 推荐） | 自写 lipsim 流体核（v2） |
|---|---|---|
| 两周可行性 | 流体核、MPI、输出、Windows 构建（T005）都现成；历史粗网格 0–1000 ns 8 进程约 6 分钟 | 流体核 + 验证需 6–8 个会话，两周内来不及 |
| 审稿认可 | PLUTO 是同行评议的开源代码（Mignone 等 2007），激波捕捉核无需自证；T005 已过 Sod/Sedov | 需自证全部流体验证 |
| 可解释性 | 本项目物理集中在少数独立文件（表格查值、EOS 接口、射线吸收、辐射源、蒸发源），每个对应一组方程与单元测试；内核以压缩包 SHA256 证明未改 | 全部自写，可通读，但数量大 |
| v2 指出的障碍 | 列积分与 MPI 冲突 → 用 `-dec N 1` 只沿 r 分区，每个进程持有完整 z 列（T009 验证）；靶耦合 → 第一层单元守恒源项；无组分扩散模块 → 用户算子或列为局限 | — |
| 代价 | 依赖 ANSYS 自带 MinGW 5.1 + MS-MPI；用 Linux（云端 GCC 13）第二平台构建并做一致性检验来对冲 | 无 |

**对可信度的影响与约束**：
1. 内核（Riemann 求解器、重构、时间推进、几何、MPI）一律不改；官方压缩包 SHA256 `1ba5527b…` 入登记表。
2. 物理只经官方扩展点进入：`init.c`（`Init`、`Analysis`、`UserDefBoundary`）、`pvte_law.c`（PVTE_LAW 的用户 EOS 模板）、`userdef_output.c`、导热/粘性系数模板。源项的挂接点（内部边界钩子或本地 `split_source.c`）由工作包 W3 选定。**凡替换任何上游文件，逐文件给出相对原版的 diff 与理由，放 `pluto/overrides/`，并在报告与补充材料中列出**（历史经验：PVTE_LAW 下导热模块需要小补丁）。
3. 物理模块写成不依赖 PLUTO 的纯 C 函数（`pluto/lip/lip_*.c`），云端用 GCC 对照 Python 参考实现做单元测试；Windows 与 Linux 两个平台跑同一组验证算例，L1 差 < 0.5%（T005 的串行/MPI 差 0.25% 为参照）。
4. 历史工程 `prior/pluto/solver/` 的任何物理代码都不复用；只参考其 Windows 构建做法。

云端无法访问 plutocode 站点（代理 403），故 T008 把官方压缩包（GPL）入库 `third_party/pluto/`，Claude 才能在云端编译测试。

## 6. 数值方法、网格与算力
- PLUTO：HD、CYLINDRICAL、PVTE_LAW、HLLC、LINEAR + RK2、多维激波展平；代码单位 1 kg/m³、1 µm、1 km/s（1 ns、1 MPa）。源项算子分裂，激光吸收与辐射带子循环（N 级）。表格 (log ρ, log T, Y) 三线性插值；ρ 10⁻⁴–3×10² kg/m³，T 250–1.5×10⁵ K。
- 计算域 r、z ∈ [0, 1500 µm]，外层拉伸。0–1000 ns（低通量到 1300 ns），每 2.5 ns 输出。

| 网格 | 内区单元（r, z < 100 µm） | 中区（到 800 µm） | 单元数（估计） | 单算例耗时（估计，T009 核实） | 用途 |
|---|---|---|---|---|---|
| G0 | 2 µm | 4 µm | 约 7×10⁴ | 8 进程约 0.3–0.5 h | 敏感性系综、Picard 迭代 |
| G1 | 1 µm | 2 µm | 约 2.6×10⁵ | 16 进程约 1.5–3 h | 基线与情景 |
| G2 | 0.5 µm | 1 µm | 约 1×10⁶ | 32 进程约 8–14 h | 网格收敛 |

网格只由收敛性决定：G1→G2 的气相吸收能量或主指标变化 > 5–10% 时加密，而不是接受。接触面压力振荡由 V5 量化，超过 1% 如实报告并评估。
- 并行策略：单算例 8–32 进程（`-dec N 1`），多算例并发，由 `lipsim.batch` 按核数预算排队；工作站留 4 核给系统，并先检查无关的 FDTD 作业占用。
