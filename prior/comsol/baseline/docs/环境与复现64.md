## 从初态构建一个新工况

```powershell
$py64 = 'D:\junlin\PlasmaPlume\runtime\Python311\python.exe'
Set-Location 'D:\junlin\PlasmaPlume\COMSOL_CuPlasma_S4_server_handoff_20261105\project'
& $py64 work/reproduce.py build REPRO64 --mesh 1 --step '0.5[ns]'
& $py64 work/reproduce.py solve REPRO64 --threads 16
```

构建基于已审核的VTE_ready初态，明确清空历史解；只改变网格因子和最大步长。网格验证用0.75；时间步验证用0.25ns。追加一级网格用0.5625及0.5ns，25009个单元。不要重复使用已存在的工况名。

本次正式协调器为`work/run_campaign64.py`，先做B64基准，再使T64/G64覆盖全部S4门宽并延长至2.12μs。它在约300ns官方保存后切换Newton策略，并使用官方CombineSolution合并真实历史。单独solve只执行一段；继续计算使用下面的resume入口。出现数值检查失败须先诊断。

追加网格由`work/run_refinement64.py`调度，预设240ns请求Newton策略切换，实际官方保存到268ns。早期采用原Jacobian复用/固定阻尼，切换后采用`onevery/auto`；方程、容差、时间步及离散不变。不要在已有协调器或worker持锁时重复启动。

## 后处理与比较

```powershell
& $py64 work/reproduce.py post MAIN
& $py64 work/reproduce.py post GRID --reference MAIN
& $py64 work/reproduce.py post TIMESTEP --reference MAIN
& $py64 work/reproduce.py compare MAIN GRID TIMESTEP
```

用实际工况名替换占位符。主例只标定一次相机响应；验证例冻结相机参数。`S4_POST_THREADS`单独控制后处理并行度。每次完整后处理结束才写入对应postprocess.json，不能用中途生成的文件宣称完成。

`B64A_PP64`、`G64A_PP64`及`G264EARLY`仅为后处理采样诊断，不是新增完整流体工况。`post_sampling_check64.json`限定五个早期有效亮度门宽；不得推广成后期极弱信号的采样收敛证明。

## 预算、停止与审计

本次墙钟窗口和每段限时见session_64.json；所有实际求解记录见solver_budget.json，包括旧平台历史。新的执行窗口须显式记录，过期的配置会阻止新求解。禁止清空历史账本。

本轮曾遇Windows短暂拒绝替换状态文件。异常保护已官方保存`G264A`到418ns，核查真实解与接续状态后恢复为`G264R1`，完整记录见`results/G264A_recovery_review64.json`。状态写入使用唯一临时文件和15秒有界原子替换重试；仍失败则保留旧状态并报错，不能删除锁绕过检查。新的PowerShell会话建议先设`$env:PYTHONUTF8='1'`，JSON显式按UTF-8读取。

数值结论分为完整时域守恒审计、S4观测门宽离散敏感性、实验吻合三部分。10%综合判据同时要求半径、面积、净灰度积分和饱和前物理亮度通过；无有效信号为不可评估。原始光子量级单独判断实验物理支持。
